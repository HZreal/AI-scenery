# AI Agent 后端应用开发学习总规划

## 项目定位

本项目用于系统学习 AI 与 AI Agent 后端应用开发。它不是单纯的资料收藏夹，也不是一次性产品项目，而是一个持续演进的学习仓库：每次聚焦一个技术点，理解核心概念，完成小 demo，然后沉淀笔记和复盘。

主线场景是“后端智能服务”。每个 demo 都尽量暴露一个可调用接口，方便后续组合成更完整的 Agent 应用。

## 学习原则

- 每次只学一个关键技术点。
- 原理理解到能解释工程边界即可，不在早期过度深挖。
- 每个主题都要有可运行 demo，而不是只停留在概念。
- demo 要记录请求样例、响应样例、错误场景和复盘。
- 语言按技术点选择，优先服务学习目标。

## 三层推进路线

### 1. 基础层

目标：能独立做出稳定的 AI 后端接口。

学习主题：

- LLM API 调用
- 消息结构与上下文窗口
- 结构化输出
- 流式响应
- Prompt 与上下文工程

阶段验收：

- 能跑通一个 AI API 服务。
- 能解释模型输入、输出、上下文、成本和延迟。
- 能写出最小测试和请求样例。

### 2. Agent 能力层

目标：能做出一个能查资料、调用工具、执行多步任务的后端 Agent。

学习主题：

- Function Calling / Tool Calling
- RAG 与知识库
- Agent Loop
- 状态、记忆与会话
- MCP 与外部能力集成

阶段验收：

- 能跑通一个带 RAG 与工具调用的 Agent 服务。
- 能观察 Agent 的步骤、工具调用、来源和错误。
- 能说明 Agent 何时应该停止、重试或请求人工介入。

### 3. 工程化层

目标：能判断一个 Agent 服务是否可靠、可控、可维护。

学习主题：

- 多 Agent 编排
- Human-in-the-loop
- 安全审批与工具权限
- Evals 与回归测试
- Trace、日志、成本和部署

阶段验收：

- 能为 Agent 服务建立评测集。
- 能追踪一次任务的完整执行链路。
- 能对高风险操作加审批和权限边界。

## 统一接口约定

每个 demo 默认至少提供一个后端调用入口：

```http
POST /api/<topic>
Content-Type: application/json
```

基础响应结构：

```json
{
  "result": "...",
  "metadata": {
    "model": "...",
    "latency_ms": 0,
    "cost_estimate": "...",
    "trace_id": "..."
  }
}
```

RAG、工具调用、Agent 类 demo 额外记录：

```json
{
  "steps": [],
  "tool_calls": [],
  "sources": [],
  "errors": []
}
```

## 学习单元模板

每个学习单元建议按这个顺序推进：

1. 核心概念：这个技术点解决什么问题。
2. 工程边界：什么时候该用，什么时候不该用。
3. 最小 demo：跑通一个后端接口。
4. 验证场景：覆盖正常输入、错误输入和至少一个边界输入。
5. 复盘：记录适用场景、坑点、下一步。
